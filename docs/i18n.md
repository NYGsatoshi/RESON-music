# Internationalization

RESON uses `next-intl` for UI localization.

## Supported locales

- `ja` — default locale
- `en` — English

Message catalogs live in `messages/ja.json` and `messages/en.json`. Keep their key structures identical; CI verifies this through `__tests__/i18n/messages.test.ts`.

## Rollout strategy

The first phase intentionally keeps the existing Japanese URL structure and rendering behavior unchanged. The request configuration therefore resolves to `ja` while UI strings are migrated out of components.

Locale-aware routing will be enabled separately with a top-level `[locale]` segment and `localePrefix: "as-needed"`, so Japanese remains prefixless while English uses `/en`. That routing change must be coordinated with authentication and the GitHub Pages static preview configuration.
